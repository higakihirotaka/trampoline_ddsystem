## 0. 決定事項

| 項目 | 決定 |
|---|---|
| 対象 | 観客・コーチ。ログイン不要。スマホ優先 |
| 公開タイミング | CJPの確定と同時 |
| 「確定のみ」の得点 | Webにも反映 |
| 集計中・インクワイアリ | 表示しない |
| 詳細（技ごとのD/E/ToF/HD、減点） | 全部公開 |
| 氏名 | 全て公開。個別の非表示機能は付けない |
| 最新タブ | 台A・台Bごとに「最後に確定した1名」。棄権は対象外。演奏中・次の選手は不要 |
| 団体総合順位 | 初回から対応 |
| データの持ち方 | 大会全体を1ドキュメント。1MBを超えそうならクラス別ドキュメントへ自動分割 |
| 作り直す場所 | CJPのブラウザ（Cloud Functionsは使わない）。再生成ボタンは付けない |
| 作り直す契機 | CJP画面の操作＋管理者の主要操作（棄権管理・決勝進出人数・決勝試技順・予選終了の指定） |
| 修正（確定解除）中 | 前の確定値を残す |
| 予選の途中経過 | 確定済みの選手だけで順位を付け、注釈は付けない |
| Q/Rマーク | 管理者が「予選終了」を指定した後にだけ表示 |
| 決勝の得点表示 | 予選点・決勝点・合計を並べる |
| 言語 | 画面の文言だけ日本語/英語を切替（氏名・所属・クラス名は日本語のまま） |
| コーチ向け機能（絞り込み等） | 初回は入れない |
| 公開制御 | 大会全体とクラス単位の公開ON/OFF、noindex |
| 旧手動公開（public_ranking） | 新機能の公開と同時に管理メニューから外してファイルも削除 |
| 公開ページの入口 | 管理メニューにURLとQRコードを表示するカードを置く |

## 1. 調査で分かった前提

- 順位・技ごとの詳細を作る処理は `public/public_ranking_gen.html` の `buildGroupSnapshot` に既にある。共通モジュールに切り出して再利用する。
- CJPの「修正」(`unlock`) はFirestoreの `published` を `false` に戻す（`officialTotal` などは残る）。「公開済みだけ」で作ると修正中の選手が順位表から消えるため、採用条件に工夫が必要（3章）。
- 管理者の棄権管理(`admin_dns.html`)は `published:true, dns:true` を書く。
- CJP画面は他の端末の確定結果を自動では更新しない。作り直しのたびにFirestoreから最新の結果を読み直す。
- ローカルにはJavaが無く、Firestoreエミュレータは使えない。ローカルのCJP画面は認証が無く書き込みが失敗するため、書き込みを伴う確認はデプロイ後の管理者アカウントでの通しリハーサルになる。

## 3. Firestoreのデータ仕様

**場所**: `tournaments/{eventId}/publicBoard/main`（分割時は `publicBoard/class_{key}` も使う）

```
main = {
  v: 1,
  updatedAt: <serverTimestamp>,
  layout: "single" | "split",
  tournament: { name, venue },
  ctl: {                                // 管理者が操作する項目（作り直しでは上書きしない）
    enabled: true|false,
    classes: { "<key>": { enabled, qualClosed } }
  },
  latest: { A: {...}, B: {...} },       // 台ごとの最後に確定した1名
  classes: { "<key>": <group> },        // layout=single の時
  index:   { "<key>": { label, docId, updatedAt } }   // layout=split の時
}
<group> = {
  label, type, cls, gender,
  rule: { numPre, scoreMode, finalScoreMode, hasFinal, finalOnly, useOnlineCard },
  counts: { confirmed, total },
  qualifying: { rows: [...] }, final: { rows: [...] },
  team: { rows: [...] } | null,
  finalCount, reserveCount
}
row = { rank, mark: "Q"|"R"|null, isDns, athleteId, name1, name2, club1, club2, finalOrder,
        qualScore, routines: { pre1, pre2, final } }
routine = { exe, diff, tof, hd, pen, score, vLimit, land,
            e[10], d[10], dv[10], t[10], h[10], dCounted[10], penReasons[] }
```

- **groupのキー**: `種目__クラス__性別` を、使えない文字を置換して作る。部分更新には `FieldPath` を使い、クラス名の文字による不具合を避ける。
- **`dv`（技ごとの難度点）**: 既存の生成処理に無いため新規に追加する。計算は `display.html` の技カードと同じ（1技上限、重複は0、指定難度のマスク）。
- **紙運用クラス（`useOnlineCard===false`）**: `d`・`dv`・`dCounted` を出さない。Eの技ごとの減点は出す。
- **E減点の取得元**: CJPが保存した `officialEPerSkill`・`officialELanding` を優先する（`ranking.html` と同じ）。
- **容量チェック**: 書き込み前に概算サイズを測る。閾値（約0.7MB）を超えたら `layout:"split"` に切り替え、`classes` を `class_{key}` の個別ドキュメントへ移し、`main` には `index` だけ残す。
- この大会の規模（結果612件）では、約0.4〜0.8MBと見込む（未実測の推定）。

## 4. 作り直しのロジック（board.js）

**入力**: 大会ドキュメント、選手（`finalOrder` 結合済み）、結果、技マスタ、団体、`ctl`。結果は毎回Firestoreから読み直す。

**結果の採用条件**
- `published===true` のもの
- `published===false` でも `officialTotal` があるもの（修正中。前の確定値を残す）
- 棄権（`dns===true`）は棄権行として含める
- 上記以外の入力途中のデータは出さない

**順位表**
- 既存のロジック（`calcQualifyingScore`、`calcFinalScore`、`compareRankEntries`、`assignRanks`）をそのまま使い、確定済みの選手だけで順位を付ける。
- 決勝は「予選との合計」方式のクラスは予選点・決勝点・合計を持たせる。
- 棄権者は順位に載せない。

**Q/Rマーク**: `ctl.classes[key].qualClosed===true` かつ `finalCount>0` の時だけ付ける。付け方は `ranking.html` の既存ルールに合わせる。

**団体総合**: `ranking.html` / `display.html` の計算（上位3名の合計、ベスト／合計方式、同点は同順位）と同じ。団体は予選のみ。団体のあるクラス×性別ごとに出す。

**latest**: 確定した選手の要約（氏名・所属・クラス・ラウンド・得点・確定時刻）。

**作り直しの範囲**: 変更が起きた選手の「種目×クラス×性別」のグループ。団体のあるクラスでは団体も作り直す。

**書き込み**: `updateDoc` で該当グループと `latest.<台>`、`updatedAt` だけを更新する。他のグループと `ctl` は触らない。

**同時実行の対策**
- 同じグループへの作り直しは1秒程度まとめて1回にする。
- 数秒後にもう一度作り直す（台AとBが同時に書いて取りこぼしても追いつくため）。

**失敗時**: CJPの確定は止めない。画面に非ブロッキングの通知を出し、数回再試行する。

## 5. 更新の契機と組み込み箇所

| 操作 | 場所 | 作り直し | latest |
|---|---|---|---|
| 確定、確定のみ | `judge_cjp.html` の `publish` | 該当グループ（団体含む） | 更新（そのCJPの台） |
| 記録主任モードの確定 | 同上 | 該当グループ | 更新しない（既定案） |
| 修正（確定解除） | `unlock` | しない（前の確定値を残す） | そのまま |
| 再表示、集計中、インクワイアリ | 各関数 | しない | そのまま |
| 得点削除、棄権の取消 | `deleteResult`、`cancelDNS` | 該当グループ | 該当選手なら削除 |
| 棄権の宣言 | `declareDNS` | 該当グループ | 更新しない |
| 棄権の設定・取消 | `admin_dns.html` | 該当グループ | 更新しない |
| 決勝進出人数・リザーブの保存 | `ranking.html` | 該当クラスの予選グループ | そのまま |
| 決勝試技順の保存 | `admin_final_order.html` | 該当クラス×性別の決勝グループ | そのまま |
| 予選終了の指定、公開ON/OFF | 新規の管理画面 | 該当グループ | そのまま |

## 6. 公開ページ（score.html）

- **URL**: `score.html?event={eventId}`。言語は自動判定し、手動で切り替えられる。
- **noindex**: ページの `<meta name="robots" content="noindex,nofollow">` と、`firebase.json` のヘッダー設定の両方で指定する。
- **購読**: `main` を1つ購読する。`layout=split` の時は表示中のクラスのドキュメントも購読する。ページが非表示の間は購読を止めて転送量を抑える。
- **状態**: 読み込み中 / 公開前（ドキュメントなし、または `ctl.enabled=false`）/ 古い表示（通信エラー・オフライン）/ 通常表示。
- **最新タブ**: 台ごとのカード（氏名・所属・クラス・ラウンド・得点）。タップで詳細。まだ確定がない台は「まだ確定した選手がいません」。
- **結果タブ**
  - 種目（個人・シンクロ・団体）→クラス→性別→ラウンドで選ぶ。
  - 順位表は、順位（1〜3位はメダル風）・氏名・所属・得点・Q/Rマーク・棄権表示。
  - 予選2本のクラスは、1本目・2本目・ベスト／合計を並べる。
  - 決勝は予選点・決勝点・合計を並べる。
  - 団体は団体順位とメンバー別の得点（採用マークつき）。
- **詳細**
  - 本ごとのタブ、D・E・ToF・HD・減点（理由つき）・合計。
  - 技ごとの表（記号・難度・E減点・ToF・HD）と着地。
  - 紙運用クラスは技ごとの記号・難度を出さない。
  - シンクロはToFの代わりにSyn、Eは小数第2位表示（`ranking.html`・`display.html` と同じ表示規則）。
- **注意書き**: 「速報であり公式結果が優先」を日本語・英語で常時表示する。
- **言語**: 画面の文言だけ切り替える。氏名・所属・クラス名は日本語のまま。

## 7. 管理画面（score_publish_admin.html）

- `ensureAdmin` で管理者のみ。管理メニューにカードを置く（旧公開カードは削除）。
- 公開URLとQRコードを表示する。QRは `cdnjs` から読み込む軽量ライブラリを使う（既存のコードにQRの仕組みは無い）。
- 全体の公開ON/OFF。
- クラス×性別の表で、公開ON/OFFと「予選終了」を指定する。最終更新、確定件数、データ容量の目安も出す。
- クラスの公開をONにすると、そのグループを作って書き込む。OFFにすると、そのグループのデータを公開ドキュメントから**削除**する（隠すだけでなく実際に消す。ドキュメントは誰でも読めるため）。

## 8. ルールと設定

- `firestore.rules` に `tournaments/{eventId}/publicBoard/{docId}` を明示する（読み込みは誰でも、書き込みは `isAdmin()`）。CJP・記録主任・管理者は既に管理者登録済みの前提。
- ルールのデプロイはhostingの自動デプロイの許可とは別なので、実施前に確認する。

## 9. 非機能・テスト

- **更新の速さ**: 確定から公開データの更新まで、通常数秒。
- **費用の目安**: 作り直しは1回あたり、そのクラスの結果とチーム分の読み取り（数十〜百件程度）。主な費用は転送量で、更新のたびに全観客へドキュメント全体（最大約0.7MB）が送られる。たとえば500人が全更新を受け取ると数十GB〜百GB規模になり得るので、購読の一時停止と容量に応じた分割で抑える。
- **テスト**
  - `board.js` は純粋関数として、実データを使ったNodeの単体テストで検証する（順位、Q/R、団体、修正中の扱い、容量判定）。
  - 書き込みを伴うCJP画面の確認はデプロイ後の通しリハーサルが必須（確定→公開ページ反映、棄権、修正、予選終了、分割）。
- **受け入れ基準**
  - 確定してから数秒で公開ページに反映される
  - 修正中も前の得点が残る
  - 予選終了前はQ/Rが出ない
  - 公開OFFのクラスのデータがドキュメントに存在しない
  - 紙運用クラスで技ごとの記号が出ない
  - 団体順位が会場ディスプレイと一致する

1. `board.js` と単体テスト
2. `score.html`（手で書いたデータで表示確認）

## 11. 確認したい点（既定案つき）

1. **公開ON/OFFが事実上の再生成になる**: クラスを公開ONにする時の作成処理は、初回の公開や漏れの手当てにも使える。OFF→ONで再生成ボタンと同じ効果になる。「再生成ボタンなし」の趣旨とずれるが、初回の作成に必須。**既定案: この動作を許容する。**
2. **記録主任の修正で `latest` を更新するか**。**既定案: 更新しない。**
3. **全体OFFの時にデータを消すか**。**既定案: 消さずに「公開前」表示のみ**（クラス個別のOFFは削除）。
4. **決勝進出人数が未設定のクラス**。**既定案: Q/Rマークは出さない。**
5. **注意書きの文言**: 固定文にするか、管理画面で編集できるようにするか。**既定案: 固定文。**

## 12. 残るリスク

- 再生成ボタンが無いため、CJPの端末が止まっている間や、更新の呼び出しが漏れた場合は、公開データが古いままになる。
- 台AとBのCJPが同時に更新するため、クラスごとの項目だけを部分更新し、他クラスを上書きしないようにする（4章）。
