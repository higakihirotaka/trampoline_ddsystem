## 0. 決定事項

| 項目 | 決定 |
|---|---|
| 対象 | 観客・コーチ。ログイン不要。スマホ優先 |
| 公開タイミング | CJPが確定したとき。確定のみ（会場ディスプレイをスキップ）・記録主任モードの確定も反映する |
| 反映しないもの | 集計中、インクワイアリ、入力途中の得点 |
| 詳細 | 本ごとのD・E・ToF（シンクロはSyn）・HD・減点＋タップで技ごとの内訳（記号・難度・E減点・ToF・HD）と着地 |
| 氏名 | 全て公開。個別の非表示機能は付けない |
| ドキュメントの分け方 | **種目×クラス×性別ごとに1つ**。予選・決勝・団体は同じドキュメントの中 |
| 公開のON/OFF | **付けない**。確定したらすぐ公開。誤確定はCJPの修正（確定解除）で対応 |
| 表示用データの保存 | 確定時に、数値＋その時点の表示用文字列を保存して凍結する（2章） |
| 選手名・所属・試技順 | 得点とは別の「名簿」に持つ。選手管理の画面で保存したときに書き直す |
| 修正（確定解除）中 | 何も書かない。前の確定値が残る（注釈は付けない） |
| 団体総合順位 | 対応する。団体は予選のみ |
| Qマーク | 予選で、決勝試技順（`finalOrder`）が決まった選手に付ける。リザーブ（R）は出さない |
| 決勝の得点表示 | 予選点・決勝点・合計を並べる（予選との合計方式のクラス） |
| 言語 | 日本語のみ。データは言語に依存しない形（記号・数字）で保存する |
| 「最新の確定」の表示 | 出さない |
| ヘッダーの「LIVE SCORES」 | 出す |
| 初期表示 | 同じ端末で、前回のフェーズ・種目を覚える。前回の選択が無い初回は未選択 |
| 更新方法 | 手動の「更新」ボタンと、「自動更新」の切替（既定OFF、30秒ごと、ページが非表示の間は止める）を実装した。リアルタイム購読は実装していない（必要になれば、後から足せる。3章） |
| 公開の緊急停止 | 手段は付けない。止めたいときは、Firebaseコンソールで公開ドキュメントを手で削除する |
| 取りこぼし対策 | 管理画面に「公開データを再生成」ボタン。進行中の大会への初回の流し込みも兼ねる |
| 公開ページの入口 | 管理メニューにURLとQRコードを表示するカードを置く（旧仕様から引き継ぎ） |
| 決勝のチップ | 決勝のあるクラスはすべて出す。決勝試技順が未確定のものは「結果がありません」と表示する |
| 検索機能 | 付けない |
| 検索エンジン | `noindex,nofollow` |

## 1. 前提（調査で分かったこと）

- **結果の確定**: CJPの `publish()`（`public/judge_cjp.html`）が `results/{eventId}_{athleteId}_{round}` に `published:true` と `officialD/E/TH/Total` などを書く。修正（`unlock`）は `published:false` に戻すだけで、`officialTotal` などは残る。
- **棄権**: `declareDNS`（CJP）と `admin_dns.html` が `dns:true, published:true` を書く。`cancelDNS`・`deleteResult`・`admin_dns.html` の取消は、フィールドの削除または結果ドキュメントの削除を行う。
- **技ごとのToF・HD**: 結果ドキュメントの `hdtsPerSkillByPanel` にある。CJPのパネルは `curPanel()` で分かる。
- **技マスタ**: `cache.js` の `getSkills` が、静的な `skills.json` と更新日時マーカーで鮮度を確認する。CJPの画面は `skillMasterMap` に保持する。
- **Firestoreのルール**: `firestore.rules` の末尾にある `match /{document=**}`（読込は誰でも、書込は `isAdmin()`）が、`tournaments/{eventId}/publicBoard/*` にも適用される。**ルールの変更は不要**。意図を残すため、エミュレータの通しテストで固定する（9章）。ルールを明示的に足す場合のデプロイは、別途承認を取る。
- **エミュレータ**: Javaが使えるようになり、`npm run test:emulator` で本物のSDKとルールを検査できる。旧仕様の「ローカルでは書込を確認できない」は解消した。
- **旧機能**: 旧手動公開（`public_ranking` / `public_ranking_gen`）は、コミット 9de52c1 で削除済み。順位・詳細を作る処理が必要なら、その前のコミットから参照できる。
- **Cloud Functions**: リポジトリに無い。使わない。

## 2. 表示用データの保存（確定時に凍結する）

**考え方**: 公開ページが技マスタ・難度計算・整形を再実行すると、技マスタの追加・編集や整形ルールの変更で、過去の表示が変わる。確定した時点でCJPの画面に出ていた内容を、そのまま保存する。

| 区分 | 保存するもの | 理由 |
|---|---|---|
| 数値（凍結） | 合計、D、E、ToF、HD、減点、棄権かどうか、有効技数 | 順位・タイブレーク・団体の計算に必要。文字列だと同点判定がずれる |
| 表示用文字列（凍結） | 技の記号、技ごとの難度・E減点・ToF・HD、着地、減点の理由、整形済みの合計・D・E・ToF・HD・減点 | 技マスタ・整形ルールの後の変更で表示が変わらないようにする |
| 凍結しない | 選手名、所属、試技順 | 確定後の訂正を、過去の確定分にも反映する。名簿に別に持つ |

- **技の記号・難度**: CJP画面に出ている値（`skillMasterMap` と、CJP画面の難度セル）をそのまま使う。難度は、重複0・1技上限・指定難度の扱いを含め、画面に表示されている値と一致する。
- **技マスタに無い技**: 試合中に技が追加された場合に備え、確定時に未解決の技IDがあれば、技マスタを強制的に取り直してから作る。それでも解決しなければ、記号を `?` とし、CJPの画面にその旨を通知する（確定は止めない）。
- **ToF・HD・E減点**: CJP画面が保持している現在の値と `curPanel()` のパネルから作る。
- **紙運用クラス（`useOnlineCard===false`）**: 技の記号と難度は保存しない。E減点は保存する。
- **整形の規則**: `public/board.js` の整形関数のとおり（旧サンプルと同じ規則）。個人のEは小数第1位、シンクロは小数第2位（E減点は10倍して個人は整数、シンクロは小数第2位）。ToFは合計が小数第2位、技ごとは小数第3位。
- **再確定**: 同じ本を再確定すると、その本の分だけが丸ごと置き換わる（フィールド単位の置換）。

## 3. Firestoreのデータ仕様と読込回数

### 3.1 場所

```
tournaments/{eventId}/publicBoard/_index           … 大会の目次（1つ）
tournaments/{eventId}/publicBoard/{グループキー}    … 種目×クラス×性別ごと
```

グループキーは `種目__クラス__性別`（使えない文字は置換）。種目は `individual` / `synchro`。

### 3.2 目次 `_index`

```
{ v:1, updatedAt, tournament:{ name, venue, startDate, endDate, colorTheme },
  groups:[ { key, type, cls, gender, label, order, hasFinal, finalOnly, hasTeam } ] }
```

### 3.3 グループのドキュメント

```
{ v:1, updatedAt,
  meta: {
    rule:  { numPre, scoreMode, finalScoreMode, hasFinal, finalOnly, useOnlineCard },
    roster:{ <選手ID>: { n1, n2, c1, c2, fo } },        // fo = 決勝試技順（無ければ null）
    teams: [ { name, members:[選手ID] } ]               // 団体のあるクラス×性別の個人グループのみ
  },
  rows: { <選手ID>: { pre1:<routine>, pre2:<routine>, final:<routine> } }
}
<routine> = {
  at,                                     // 確定時刻
  dns,                                    // 棄権なら true（他は省略）
  total, d, e, tof, hd, pen,              // 数値（凍結）
  vl,                                     // 有効技数
  s: { total, d, e, tof, hd, pen },       // 整形済みの表示用文字列
  sk: [ { sym, dd, e, tof, hd } ×10 ],    // 技ごとの表示用文字列（紙運用クラスは sym・dd を省く）
  land,                                   // 着地のE減点（文字列）
  bn,                                     // Dのボーナス（文字列。0なら空。紙運用は出さない）。内訳のL行の難度の列に「+0.3」と出す
  pr: [ "減点の理由", ... ]
}
```

- **団体**: 団体は、同じクラス×性別の個人グループの `meta.teams` と `rows` から、閲覧者のブラウザで集計する（上位3名の合計、ベスト／合計方式、同点は同順位。`ranking.html` と同じ）。
- **順位・Qマーク・団体合計**: サーバー側では計算しない。閲覧者のブラウザで、`shared.js` の共通関数（`calcQualifyingScore`、`calcQualifyingTb`、`calcFinalScore`、`compareRankEntries`、`assignRanks`）に `rows` の数値を渡して計算する。
- **容量**: 1本あたり約0.7KB、1グループ（最大約35名×3本）で約70KB程度の見込み（未実測）。1MBの上限に対して十分に小さい。再生成ボタンで、グループごとの容量を表示する。

### 3.4 読込回数

| 場面 | 今のサンプル（参考） | 新方式 |
|---|---|---|
| ページを開く | 約1,000回（結果約600＋選手を2回読んで約350＋団体など） | **2回**（目次1＋表示するグループ1。前回の選択が無ければ目次の1回だけ） |
| 種目を切り替える | 0回（読み込み済み） | 1回（同じ種目は、更新までメモリに保持して読み直さない） |
| 更新ボタン | 約600回 | **1回**（表示中のグループ） |
| CJPの確定（書き込み側） | 0回 | **0回**（読まずに、その1本の分だけ書く）。書込は1回 |

- 例: 300人が各5種目を見ると、約1,500回。旧方式の約30万回の数百分の1。
- 自動更新（30秒ごと）を2時間ONにすると、1人あたり約240回。300人なら約7万回（1日の無料枠は5万回）。更新方法が保留でも、この範囲に収まる。リアルタイム購読の場合は、見ているグループが更新されるたびに、購読者1人につき1回読む。更新の頻度は、1グループあたり1本の確定ごと。
- 閲覧者のブラウザでは、ページが非表示の間は自動更新を止める。

## 4. 書き込みの契機

書込は、すべて**フィールド単位の更新**（`updateDoc` ＋ フィールドパス）にする。台AとBのCJPが同時に確定しても、別のフィールドなので衝突しない。ドキュメントが無い場合は、名簿と団体を含む初期のドキュメントを `setDoc` で作ってから書く（CJPの画面は、選手と大会設定を既に読み込んでいる）。

| 操作 | 場所 | 公開データへの書込 |
|---|---|---|
| 確定、確定のみ、記録主任の確定 | `judge_cjp.html` の `publish` | `rows.<選手ID>.<ラウンド>` に routine を書く |
| 修正（確定解除） | `unlock` | **書かない**（前の確定値が残る） |
| 再表示、集計中、インクワイアリ | 各関数 | 書かない |
| 棄権の宣言 | `declareDNS` | `rows.<選手ID>.<ラウンド>` に `{dns:true, at}` |
| 棄権の取消、得点の削除 | `cancelDNS`、`deleteResult` | 該当フィールドを `deleteField()` で削除 |
| 棄権の設定・取消 | `admin_dns.html` | 同上（棄権は書込、取消は削除） |
| 選手の保存（氏名・所属・決勝試技順など） | `athlete_management.html` の保存 | 最新データを読み直して、**すでにある**公開ドキュメントの `meta.roster`（と `meta.teams`・`meta.rule`）、目次を書き直す。無いドキュメントは作らない（大会の準備中に、選手名が公開されないように） |
| 決勝試技順の保存 | `admin_final_order.html` | 該当グループの `meta.roster` の `fo` |
| チームの保存・削除 | `team_setup.html` | 該当グループの `meta.teams` |
| クラスのルールの保存 | `class_rules.html` | 該当グループの `meta.rule`。目次も更新 |
| 再生成 | 管理画面のボタン | 全グループと目次を、結果から作り直す（5章） |

- **公開ドキュメントを最初に作るのは**、そのグループの最初の確定（または棄権）の書込、または再生成。このとき、名簿の骨組みと目次（無ければ）を、最新データを読み直して作る。
- **失敗時**: CJPなどの本来の処理は止めない。画面に非ブロッキングの通知を出し、数回やり直す。それでも失敗したら、再生成ボタンで直す。
- **選手管理以外の変更**（`entry.html`、`bulk_entry.html` など）は名簿に自動では反映されない。反映が必要なら再生成ボタンを押す。

## 5. 公開データの再生成（管理画面）

- 管理メニューのカードに置く（URLとQRコードの表示と同じ画面）。管理者のみ（`ensureAdmin`）。
- **処理**: 大会・選手・団体・クラスのルール・技マスタ・結果をすべて読み、全グループと目次を作り直して `setDoc` で書く。結果の採用条件は「`published===true`、または `published===false` で `officialTotal` がある（修正中）。棄権は `dns===true`」。入力途中のデータは出さない。
- **用途**: 進行中の大会への初回の流し込み、書込の取りこぼしの修正、選手管理以外で変わった名簿の反映。
- **注意**: 作り直しの最中に確定が入ると、その1本が古い内容で上書きされることがある。確定が止まっているときに押す。画面にも、その旨を表示する。
- 管理者の読込は、1回あたり数百〜1,000件程度。
- グループごとの容量と、確定件数を結果として表示する。

## 6. 公開ページ（`score.html`）

- **URL**: `score.html?event={eventId}`。`noindex,nofollow`（ページの `<meta>` と `firebase.json` のヘッダーの両方）。
- **構成**: 旧サンプルのレイアウトを土台にした（`public/score.html`）。ヘッダー（大会名・会場・日付、「LIVE SCORES」、更新時刻、注意書き、更新・自動更新ボタン）、固定ナビ（フェーズ：予選・決勝・団体、種目：個人・シンクロ・団体のチップ）、順位のカード。
- **選択**: 同じ端末の `localStorage` に、フェーズと種目を保存して、次回開いたときに復元する。保存した種目が目次に無ければ、未選択にする。`localStorage` が使えなくても動く。
- **順位のカード**: 順位（1〜3位はメダル風）、氏名、所属、合計点、Qマーク、1位との差。本ごとにD・E・ToF（Syn）・HD・減点。ベスト方式のクラスは採用した本を示す。タップで技ごとの内訳。
- **決勝**: 予選点と決勝点を並べる。決勝チップは、決勝のあるクラスをすべて出し、まだ誰も確定していないものは「結果がありません」と表示する。
- **団体**: 団体順位とメンバー別の得点（採用した得点を強調）。
- **状態**: 読み込み中 / 公開前（目次がまだ無い）/ 古い表示（通信エラー・オフライン）/ 通常表示。
- **注意書き**: 「速報のため、最終的な公式結果が優先されます」を常時表示する。
- **配色**: 大会の配色設定が赤の場合は赤系にする。ダークモードに対応する。

## 7. 管理画面

- **管理メニューのカード**（新規）: 公開URL、QRコード（`cdnjs` の軽量ライブラリ）、「公開データを再生成」ボタン、結果（グループごとの容量・確定件数・最終更新）。
- 公開ON/OFFと「予選終了の指定」は作らない。

## 9. テスト

- **単体テスト**（`npm test`）: `board.js` の純粋関数を、実データに近い入力で検証する。routine の組み立て（個人・シンクロ・紙運用・技マスタに無い技）、整形の規則、順位・Q・団体の計算、修正中の扱い（確定解除後も前の値で順位を計算できること）。
- **エミュレータ**（`npm run test:emulator`）: 本物のSDKとルールで、公開ドキュメントを、認証なしで読める・書けない、管理者は書ける、フィールド単位の更新が別の本を壊さない、同時に別の本を書いても両方残る、削除が効く、を確認する。
- **通しリハーサル**（デプロイ後、管理者アカウント）: 確定→公開ページへの反映、確定のみ、記録主任、修正、棄権と取消、得点削除、選手名の訂正、再生成。
- **受け入れ基準**
  - 公開ページを開いたときの読込が、目次とグループの数回で済む
  - 確定から数秒で、公開ページを更新したときに反映される
  - 修正中も前の得点が残る
  - 技マスタを後から編集しても、確定済みの表示が変わらない
  - 試合中に追加した技が、記号つきで表示される
  - 紙運用クラスで、技の記号が出ない
  - 団体順位が会場ディスプレイ・`ranking.html` と一致する
  - 選手名を訂正すると、過去の確定分にも反映される

## 10. 実装の順序

1. `board.js` と単体テスト
2. `score.html`（手で書いたデータで表示確認）。エミュレータでのルール確認
3. `judge_cjp.html` への組み込み（`publish`、棄権、削除）
4. 他の画面への組み込み（選手管理、決勝試技順、チーム、ルール、`admin_dns.html`）
5. 管理メニューのカード、再生成ボタン、URL・QR
6. デプロイ後の通しリハーサル（済み）
7. `score_public_sample.html` の削除（済み）

**リハーサルの手順**（確認用の大会、または確定を止めた状態で）:

1. 管理メニューの「公開スコアページ」を開き、URL・QRが出ること、「現在の公開データ」が空（または現況どおり）であることを確認
2. 「公開データを再生成」→ 公開ページ（別の端末・ログインなし）で、種目・クラスを選んで表示されること。確定済みの得点があれば、順位・内訳が `ranking.html` と一致すること
3. CJPで1本確定 → 公開ページの「更新」で反映（数秒以内）。D・E・ToF・HD・減点、技ごとの内訳が出ること
4. 「確定のみ」、記録主任モードの確定も反映されること
5. 「修正」（確定解除）→ 公開ページは前の得点のまま。再確定で置き換わること
6. 棄権の宣言／取消、得点の削除、`admin_dns.html` の棄権の設定／取消 → 公開ページに反映されること
7. 選手管理で氏名を訂正して保存 → 過去の確定分にも反映されること。決勝試技順を保存すると、予選の Q マークが付くこと
8. 技マスタに技を足して、その技を使った本を確定 → 記号つきで表示されること。技マスタを後から編集しても、確定済みの表示が変わらないこと
9. 紙運用クラスで、技の記号が出ないこと。団体の順位が `ranking.html` と一致すること
10. 大会の準備中（公開ドキュメントが無い状態）に選手管理を保存しても、公開ページに選手名が出ないこと

## 11. 残るリスク

- **反映の漏れ**: 書込の組み込み箇所が約10か所ある。漏れは、再生成ボタンで直す。
- **再生成との競合**: 再生成の最中の確定が上書きされることがある（5章）。運用で避ける。
- **CJPの端末が止まっている間**: その間の確定は、公開データに反映されない。復旧後に、該当の本を再確定するか、再生成ボタンを押す。
- **技マスタの鮮度**: CJPの画面が古い技マスタを持っていると記号が解決できない。確定時に強制的に取り直すことで対処するが、取り直しにも失敗した場合は `?` と表示される。
- **名簿の反映**: 選手管理以外で名前が変わると、再生成するまで反映されない。
- **計算の二重化**: 順位の計算は、`ranking.html` と公開ページの両方にある。共通関数（`shared.js`）を使うことで、ずれを防ぐ。
