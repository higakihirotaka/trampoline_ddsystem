# 会場ディスプレイ／大会画面コントロール 刷新仕様（案）

状態: 設計合意中（実装は未着手）。得点表示のレイアウト（スコア・順位表の見た目）は変更しない。
目的: 画面のコントロールをしやすくする。休憩中に残り時間を出しながら、いろいろな画面を出せるようにする。

## 1. 合意した要件

| # | 項目 | 決定 |
|---|---|---|
| 1 | タイマーの重ね表示 | 「角のバッジ」と「下の帯」を切り替えられる。位置（右上・左上・右下・左下）を選べる。**設定は全ディスプレイ共通** |
| 2 | 切り替え操作 | 標準は「プレビューして、会場に出す」。「押したらすぐ会場に出す（ワンタップ）」にスイッチで切り替えられる。「前の画面に戻す」ボタンを付ける |
| 3 | CJP の確定 | 今のとおり（確定した瞬間にスコア画面へ強制切替し、そのまま残る）。割り込み層は作らない |
| 4 | 自動で順に回す画面（プログラム） | ロゴ、大会タイトル、順位表（クラス巡回）、選手紹介、決勝スタートリスト、団体順位、お知らせ文 |
| 5 | 操作する端末 | PC（Windows / Mac）とタブレット。スマホは対象外 |
| 6 | 操作者 | 1人。同時操作の競合対策は最小限（後から書いた方が勝つ） |
| 7 | ディスプレイ | 台数は変わる。**同じ種類の画面を、ディスプレイごとに独立して切り替える** |
| 8 | お知らせ文 | 自由入力＋よく使う文を保存して呼び出せる。最大3行、文字サイズ調整（タイトル画面と同じ作り） |
| 9 | CJP の確定と複数ディスプレイ | ディスプレイごとに「CJP に従う」スイッチを付ける。オンのディスプレイだけが、CJP の確定でスコア画面になる（標準はオン） |
| 10 | ディスプレイの名前 | URL に付ける（）。名前の無い URL は「メイン」 |
| 11 | 接続状況の表示 | 出す。操作画面に「メイン 接続中」「サブ 切断（最後の応答 30秒前）」のように表示する（ルール変更を伴う。大会の合間に実施） |

## 2. 保持する画面

スコア（個人スコア＋順位表。CJP が出す「集計中」「問い合わせ」を含む）／ロゴ／大会タイトル／表彰式／タイマー全画面（今の「会場練習」）／順位表 巡回／選手紹介／決勝スタートリスト／団体順位（CJP が出す）／**お知らせ文（新規）**。

各画面の中身（描画）は変えない。変えるのは「何を出すかの決め方」と「操作画面」。

## 3. 画面の層

```
オーバーレイ層  タイマー（残り時間）…バッジ or 帯。全ディスプレイ共通設定。どのメイン画面にも重ねられる
メイン画面      上の保持する画面のどれか。ディスプレイごとに独立
```

- タイマーは、メイン画面とは独立した部品にする（今は「会場練習」画面と選手紹介の右上にしか出ない）。
- 「タイマー全画面」は、メイン画面の1つとして残す。
- オーバーレイのラベル（例: 「Aクラス 練習」）は、今のクラス名設定（class1/class2）を使う。

## 4. ディスプレイごとの切り替え

- 会場ディスプレイは、URL で名前を持つ: `display.html?event=…&screen=メイン`（省略時は「メイン」）。
- 操作画面の上部に「操作対象」のチップ（全部 / メイン / サブ …）を置く。標準は「全部」。
- 表示する画面の決め方（CJP の書き込みを変えずに済ませる）:
  - 全体の基準: 今の `venueScreen`（CJP が書く）。
  - ディスプレイごとの上書き: `{ scene, params, at }`。
  - 各ディスプレイは、**新しい方**を表示する。
  - 操作画面の「全部」への切り替えは、基準を更新して上書きを消す。
  - CJP が `venueScreen` を書いたら、「CJP に従う」がオンのディスプレイが、その画面になる（標準はオンなので、今と同じ挙動）。オフのディスプレイは、操作画面で切り替えた画面を保つ。
- 「新しい方」の判定のため、CJP の `venueScreen` 書き込み（3か所）に `venueScreenAt: serverTimestamp()` を足す（小さな変更）。
- 接続状況: ディスプレイが定期的に「接続中」の印を書き（名前、最後の応答時刻、いま出している画面）、操作画面が一覧する。印を書く先の追加は、firestore.rules の変更が必要（ログインなしで書ける項目を限定する。段階5）。

## 5. 操作画面（display_control）の構成

画面の配置（PC・タブレット共通。タブレットは2列を1列にして、プレビューを折りたたみ式にし、ボタンを大きくする）:

1. **上部の固定タイマー帯**: 残り時間、開始・停止・リセット、プリセット、±30秒、繰り返し、「会場に重ねる」のオン・オフ、バッジ／帯と位置。
2. **操作対象のチップ**（全部／メイン／サブ…）。
3. **画面タイル**（競技／進行・式典／休憩・つなぎ にグループ分け）。いま会場に出ている画面は緑、プレビュー中は青。
4. **プレビュー**: 実際の `display.html` を縮小して埋め込む（読み取り専用）。「会場に出す」「前の画面に戻す」。ワンタップモードのスイッチ。
5. **設定ドロワー**: タイルの歯車から開く。変更は自動保存し、「自動保存済み」を表示する（保存ボタンは廃止）。
6. **プログラム**: 画面の並びと秒数を登録して、順に回す／ループ。よく使う組み合わせを保存して1タップで呼び出す。
7. **お知らせ文**: 自由入力＋保存した文の一覧。

キーボード（PC）: 数字キーでタイル選択、Enter で「会場に出す」、Space でタイマーの開始・停止。

プレビューの仕組み: `display.html?preview=1` は、操作画面から `postMessage` で「この画面・この設定を描画」と受け取り、Firestore には何も書かない。スコア画面は、実際のデータをそのまま読む。

## 6. プログラム（自動切り替え）

- 構成: `[{ scene, params, durationSec }, …]`、ループの有無。
- 計算は会場ディスプレイ側で行う（選手紹介と同じ方式）。書くのは、開始時刻（サーバー時刻）とプログラムの ID だけ。
  - 操作PCが別ページに行っても、閉じても止まらない。
  - 途中でリロードしても、開始時刻から正しい位置に戻る。
- 順位表の巡回、選手紹介は、「長さが決まらない項目」として扱う（今の巡回・紹介の進行をそのまま使い、終わったら次の項目へ）。
- ディスプレイごとに、別のプログラムを走らせられる。
- 「手動で次へ・前へ」を用意する。

## 7. データ構造

最終形（段階6）は、大会ドキュメントの分割（`venue-display-doc-split-phase2` と同じ方針）。

- `tournaments/{id}`: 大会設定のみ
- `tournaments/{id}/live/venue`: 基準の画面、ディスプレイごとの上書き、タイマー、オーバーレイ設定、プログラムの実行状態
- `tournaments/{id}/venue_settings`: 配色、各画面の設定、お知らせ文と保存した文、プログラム、保存した組み合わせ

段階5までは、今の項目（`venueScreen`、`warmupSettings` など）を読み書きし、新しい項目は足すだけにする。分割は、古い項目と新しい項目の両方を読む期間を設けてから切り替える。

## 8. 進め方

| 段階 | 内容 | リスク |
|---|---|---|
| 1 | タイマーのオーバーレイ化（バッジ／帯・位置・全画面共通）と、今の操作画面のタイマー帯の固定 | 小 |
| 2 | 新しい操作画面（別URLで並行）: タイル、プレビュー、ドロワー、自動保存、前の画面に戻す、ワンタップモード、お知らせ文と保存した文 | 中 |
| 3 | ディスプレイごとの切り替え（名前、上書き、操作対象チップ、CJP の `venueScreenAt`） | 中 |
| 4 | プログラム（自動切り替え）と、保存した組み合わせ | 中 |
| 5 | ディスプレイの接続状況の表示（ルール変更を伴う） | 中 |
| 6 | 大会ドキュメントの分割（大会の合間に、テスト大会で確認） | 大 |

- 各段階で、テスト用の大会（`ZZTEST…`）を作り、複数タブで実機確認する。確認後に削除する。
- 純粋な計算（表示する画面の決定、プログラムの現在位置、タイマー）は `npm test` に入れる。
- 古い操作画面は、新しい画面が安定するまで残し、すぐ戻せるようにする。
